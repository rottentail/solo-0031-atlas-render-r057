# 运行与恢复

生产启动前构建 `go build -o atlas ./cmd/atlas`。通过ATLAS_STATE指定独立可写状态路径，通过ATLAS_ADDR指定受信环境的监听地址。状态目录应由运行进程拥有；临时写文件与最终文件位于同一个目录。

同一状态路径的第二个进程会因为独占文件锁拒绝启动。锁文件可长期存在，锁的有效性由操作系统进程锁决定。不要通过删除锁文件启动第二个写进程。

SIGTERM或中断信号会停止领取任务，取消执行中的计算，等待HTTP请求和执行循环结束。执行中的任务保留running，下一次启动会重新入队。SIGKILL恢复用 `python3 scripts/walkthrough.py --workflow recover-render` 演练；只会结束该脚本自己启动的实例。

备份时先正常停止实例，复制状态JSON；恢复时向空的独立状态路径复制，再启动。不要把运行中手工编辑过的JSON直接作为新事实。启动校验拒绝不支持版本、损坏摘要、孤立关联和非法文档。备份包含PNG字节与全部快照引用闭包，无需从外部素材服务恢复。

容量观察入口是GET /v1/status。它报告未压缩的持久结果PNG字节总量和各任务状态数量，不代表堆内存峰值。`capacity` 块报告实际生效的容量门禁（`queueDepthLimit`、`queueBytesLimit`、`workPixelLimit`、`assetBytesLimit`）、当前未结束承诺用量（`queueDepth`、`queueBytes`）、运行时边界（`gomaxprocs`、`memoryLimitBytes`）和 `accepting` 接收状态；`accepting` 为 false 时新提交将返回 429。完整状态在事务中复制并编码，因此长期积累会增加提交成本。当前未提供任务或快照删除；部署应按预期数据量规划状态盘和实例周期。结果清理入口仅删除PNG字节。历史事件超过500条会截断，但sequence继续增加。

## 容量门禁与运行保护

上线容量门禁分两层，全部阈值可用环境变量收紧，非法取值使启动失败：

| 环境变量 | 默认 | 含义 |
|---|---|---|
| ATLAS_WORK_PIXELS | 40000000 | 单任务编译工作量（图层像素）上限 |
| ATLAS_ASSET_BYTES | 67108864 | 单任务解码素材字节上限 |
| ATLAS_QUEUE_DEPTH | 64 | 未结束任务（queued+running）数量上限 |
| ATLAS_QUEUE_BYTES | 268435456 | 未结束任务驻留字节估计（素材字节+输出缓冲）上限 |
| ATLAS_MEMORY_LIMIT | 不设置 | 进程软内存上限字节；标准 GOMEMLIMIT 已设置时优先 |

门禁拒绝返回429且不写入任何事实：不留下排队承诺，幂等收据也不被消耗，同一键可在腾出容量后复用。已接受的承诺不受门禁影响，重启后照常恢复执行。GOMAXPROCS 由 Go 运行时按环境变量读取，应与 CPU 配额对齐；`deploy/atlas.service` 给出了 cgroup 硬边界（MemoryMax、CPUQuota）与进程内软边界一致的示例，软边界应更低，让服务在触及硬边界前自行返回 429。健康、状态、事件和任务查询走只读轻量路径，不随已接受承诺的数量复制状态，队列饱和时取消与健康查询仍保持有界延迟。

受限环境演练 `python3 scripts/capacity_drill.py` 是可重复的上线前检查：在 GOMAXPROCS=1、128 MiB 软内存上限和收紧的队列门禁下启动真实进程，依次验证超预算拒绝、解码素材内存门禁、高倍输出、嵌套图层确定性、连续小任务、队列数量与字节门禁、过载期间的健康/取消边界，以及 SIGKILL 后已接受承诺的恢复与幂等收据重放。演练使用临时状态目录和临时端口，失败时以非零退出。

故障时保留当前状态文件和服务日志，在副本上检查。500表示事务未能完成；客户端可先读取原请求目标确认状态。提交任务时使用稳定幂等键，不能因为连接中断盲目换键。409应结合当前场景revision、快照state或收据语义判断。410说明成功结果字节已清理，任务成功事实仍保留。

`deploy/atlas.service` 是Linux systemd配置示例，需按实际用户、二进制和状态路径调整。macOS可直接运行同一二进制。当前未验证容器部署、跨进程共享写入、跨机器文件系统锁或网络存储。
